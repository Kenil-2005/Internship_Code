01 · Objective

Build the full CRUD flow, end to end

An Angular form and list view, an ASP.NET Core Web API, and a SQL Server table. This prototype is a clickable reference for what the finished screens should do — it is not the real app, and it holds no server or database. Use the toggle in each screen to reveal the exact spec line behind a field.

In scope
  • One reactive form, reused for Create and Edit
  • Customer list with per-row Edit and Delete
  • Client-side validation on all nine fields
  • Create, list, update, delete API endpoints
  • One SQL Server table (EF Core, code-first)
  • Success / error message after every action
  • Confirmation prompt before delete
Out of scope
  • Unit tests, SonarQube scan, formal PR review
ASP.NET Core Web API Angular Reactive Forms SQL Server + EF Core 9 form fields

Goal is hands-on CRUD practice — keep the implementation simple and functional, not production-grade.

06 · Definition of done

Acceptance criteria

Your implementation is done when every item below is true against your own build — this prototype only mimics the front-end behavior described in each line.

  • Submitting the form with valid data creates a row in the Customers table, including Gender, Country, and State
  • Required fields, email format, and the new Gender/Country/State selections are validated before submission
  • The password is stored as a hash, not plain text, and is left unchanged on update unless a new one is provided
  • The customer list displays all registered customers and updates after any create, edit, or delete action
  • Editing a customer pre-fills the form and updates the correct row in the Customers table
  • Deleting a customer prompts for confirmation, then removes the row from the Customers table and the list
  • A success or error message is shown to the user after each create, update, and delete action
